## Current state (2026-10-29)
- `pcb_current_sim/`: a general DC + electro-thermal solver package. It has a CLI (`python3 -m pcb_current_sim`) and two GUIs with the same features:
  - `wxgui/`, used inside KiCad because the Flatpak Python has wx but no Tk;
  - `gui/` (Tk), for standalone use on the host.
  - Shared helpers for both live in `tables.py`.
  - `kicad_plugin/action.py` prefers wx and falls back to Tk.
- Docs (git repo since 2026-10-29): `README.md` is a short overview with screenshots. The full reference is `docs/USER_GUIDE.md` (update that one when features change). `docs/DEVELOPMENT.md` covers environment, tests and layout, and `docs/ROADMAP.md` copies the plan below.
  - Screenshots in `docs/screenshots/` are regenerated by `sim/demo/screenshots.py` (Flatpak + plugin venv). It grabs from the screen, so the user must not use the PC while it runs.
- Tests: `python3 -m pytest tests` (115 tests, about 60 s; 19 in `tests/test_suite.py`, 10 in `tests/test_matching.py`, 16 in `tests/test_extract.py`, 31 in `tests/test_loop.py`, 5 in `tests/test_linsolve.py`). `cold()` in the tests turns magnetic off; magnetic tests turn it back on.
- Row kinds (`Row.kind`):
  - `"I"` is a current path, `"load"` a current sink (+ → −), and `"V"` a voltage source (Norton, `G_SOURCE` = 1e6 S).
  - The `current` field holds amps or volts; the JSON key name is kept for compatibility.
  - `Network.solve` is split into `_assemble` / `_solve_system` (multi-RHS) / `_post`.
  - `solve_unit_rows` gives each row's 1 A loop for the inductance calculation; a V row has its own source removed.
- `magnetic.py`:
  - Moments go on a `MomentGrid` (crop + 3 mm). `FFTConv` is a circular FFT with cached kernels, sized at least 2n−1.
  - B is computed on planes above and below the board. In board axes (y down, z up) the Biot–Savart signs are written out explicitly.
  - Inductance is a Neumann sum plus Grover for barrels; each row's loop is closed by a filament from the exit pads to the entry pads.
- Pulse (`run_pulse`):
  - It uses its own `ThermalModel` (crop + 3√(α_cu t)). The state is θ0 + φ, and φ is driven by heat(t) − heat_base.
  - FR4 capacity: the stepping matrix uses the start-of-window value (`CAP_STEP` 1.25), and the growth sink C′φ is applied every step, so T(t) is smooth. It is about 1.6 % conservative against converged.
  - It keeps about `PULSE_FRAMES` = 20 coarse snapshots (`res.pulse_frames`, saved in the npz as `P:n|layer`).
  - `RESOLVE_K` 20 K.
- 3D view:
  - `export.figure_3d` / `export_html_3d(js="local"|"inline"|"cdn")`. Surfaces are capped at 20k cells and sent as float32.
  - The wx viewer's top pane is a notebook: "2D map" and a lazily built "3D" tab using `wx.html2.WebView` with local plotly.js.
  - `WEBKIT_DISABLE_DMABUF_RENDERER=1` is set in `wxgui/viewer.py`; without it WebKit in the Flatpak shows a blank page ("Failed to create GBM buffer").
  - The result summary stores `layer_z_mm`, `z_bottom_mm` and `board_outline`, and vias store `L_top`/`L_bot`. Older saved results have no 3D tab.
- `vtk_export.export_vtk(res, dir)` writes board.vtm, data/*.vti|vtp and pulse.pvd (zlib + base64), using numpy only.
  - y is flipped to point up, and J and B vectors are flipped with it.
  - Validated with VTK 9.7 readers (installed into a scratch venv, not a dependency). ParaView itself is not installed here.
- Thermal (fix 2026-10-29, after the user reported temperatures reading high on Magnus_Gateway):
  - `h_auto` (default on): per-face h = 1.42·(ΔT/L)^0.25 + εσ(T⁴−Ta⁴)/ΔT at the local rise, with L = √(thermal area).
    It is solved as a fixed point with CG preconditioned by the LU at the initial h (`h_conv`), so there is no refactorisation.
    The summary's `h_conv` holds the mean h.
  - Via and plated-hole barrels (all nets) conduct heat between layers.
  - Element heat is a 5-tuple `(x, y, L, W, pad geom)`, spread over the pad's coverage (cached).
  - Effect on Magnus_Gateway (4.1 W in six 0.5 Ω 2512): T_max 132.6 → 115 (pads + vias) → 106 °C (auto h).
    The board-mean rise of about 46 K is plain P/(2hA).
  - `Polygon.lattice` is a scanline even-odd fill used by `raster.coverage` for zones.
    It replaced matplotlib `contains_points`, which took 39 of the 52 s thermal setup on that board.
- Elements have a `heats` flag (false = off-board load or wire; CLI suffix `:ext`).
- Resistance elements (`elements.py`):
  - Resistor footprints are auto-detected from the Value field.
  - User elements are any two pads plus R (FET R_on, DCR, external loads).
  - Rows may span nets when elements connect them; pads on one side must share a net.
  - The scenario JSON stores only user elements and disabled auto ones, and `merge()` re-detects the rest.
  - Element I²R is point heat at its pads.
  - 2026-10-30: `Element.model` "R" (resistance) or "V" (constant drop: Vf + R in series, conducting a → b only, i.e. a diode; CLI `A-B=0.45V+20m`). `Network.solve` iterates the on/off states (`net.el_on`, kept between solves); a blocked diode has G = 0 and is left out of the matrix. Unit-row solves (inductance) drop Vf.
  - 2026-10-30 fix: large boards crashed with a shape mismatch in the old pyamg (n > 150k) path; that path is now gone (see Speed).
- Speed (2026-10-30 overhaul, after the user asked whether C / OpenCL / another solver would help):
  - Profiled on Magnus_Gateway_flowway (the user's saved scenario: thermal + error estimate + magnetic): 24.4 s, of which 13 s was SuperLU factorising a 468k-node thermal grid (0.18 mm) and 7 s the h_auto CG; electrical (84k nodes) ~1 s. Python glue was ~10 %, so a C rewrite would not help.
  - Measured alternatives: PARDISO (MKL) 10x faster factorisation but ~950 MB of wheels; cholespy/CHOLMOD no faster (no METIS/threads); pyamg 127 CG its on the thermal matrix and 50x slower + 8 % wrong on electrical at 0.7M nodes (high copper/FR4 contrast); a geometric nested-dissection ordering fed to SuperLU did not reduce fill. GPU/OpenCL rejected: only helps iterative methods, which fail here; the PC has an AMD iGPU sharing RAM bandwidth.
  - Done: `linsolve.py` (single solve layer: SuperLU, optional PARDISO if `pypardiso` imports, CG on MemoryError; env `PCB_SIM_SOLVER`); pyamg path removed (0.7M nodes: 5.8 s total, exact); thermal cell `Settings.thermal_pitch` = 0.3 mm (`thermal.PITCH`; MAX_CELLS 300k is now only a cap); `raster.coverage_all` is a true union on a ~30 µm sub-lattice (the old per-primitive max at S=2 under-counted copper and scattered T_max by ±2.5 K); `solver.cached()` keeps the last raster / coarse raster / thermal / pulse thermal model per board object + key (`ThermalModel.reset(s)` restores h and takes the new settings); a ThreadPoolExecutor builds the thermal model during the electrical solve, runs the error-estimate solve alongside, and B planes alongside the inductance solve; magnetic FFTs use `workers=-1`. SuperLU and pocketfft release the GIL (checked).
  - Result on Magnus: 8.0 s first run, 4.6 s re-run, T_max 102.5 °C (0.18 mm with the coverage fix: 104.1; old code 106.3). Demo board 0.3 mm: -1.1 K of a 130 K rise.
  - Tried and reverted: cut-cell face apertures in the thermal sheet (cells ~ trace width at 0.3-0.6 mm: T_max scattered 106-122 °C); refactorising the h_auto preconditioner at the converged h (2.2 s factor > 0.9 s saved at 2 iterations).
  - Remaining ideas: non-uniform thermal mesh (fine near copper clearances, coarse in the margin) would remove the coarse-cell bias; the h_auto CG loop (~2.7 s) and b_planes' per-via loop (~0.8 s) are the next costs.
  - The grid is cropped to the copper of the simulated nets, snapped to the board lattice so results are identical.
  - The thermal grid is independent (crop + `thermal_margin` 20 mm) and mapped via `Pr`/`Pc` matrices.
  - splu uses `MMD_AT_PLUS_A` + SymmetricMode (about 3× faster than COLAMD).
  - Demo board `sim/demo/demo.kicad_pcb`: 20 s → 3.9 s.
  - `sim/demo/smoke_loop.py [BOARD]` (default `sim/demo/buck_demo.kicad_pcb`, generated from `tests/test_loop.py:buck_cell(text=True)`) smoke-tests the Switching Loop window.
- `sim/demo/smoke.py` is a wx GUI smoke test. Run it with the plugin venv python inside the Flatpak; it writes screenshots next to itself.
- Reference validation, with thermal off: 27.21 mΩ signal and 20.24 mΩ GND. The old script gave 27.3 mΩ; its staircase raster read slightly high on the diagonals.

  - Excitation is current only.
  - The front end is the IPC API, not SWIG. SWIG is deprecated in KiCad 10 and removed in the 11 nightlies.

## Trace R/L/C → SPICE (built 2026-10-30)
- The user asked for a utility estimating DC R, parasitic L and C of any trace / geometry, "useful in any simulation from onwards". Their answers: board types **both 2-layer and 4+ layer equally**; selection by **two or more pads**; outputs **summary table, SPICE subcircuit, board highlight**, plus (low priority) a **drawn schematic of the SPICE model** with series/shunt R, L, C; SPICE target **any SPICE, plain RLC only**.
- Core `pcb_current_sim/extract/` (toolkit-neutral):
  - `path.build`: graph of the net's copper from port 1: straight track pieces (arcs as polylines), T-junction splits, touching ends joined (within half the narrower width), pads (one node per pad id), via nodes per layer with barrel edges, each zone polygon = one node (warned). `stubs=True` keeps the whole component, else shortest paths only.
  - `xsection.solve`: 2D finite-volume Laplace on a graded rectilinear grid (`_fill` ratio 1.25), signal 1 V, return 0 V, zero-flux outer box; C' with dielectrics, C0' in air, L' = 1/(c²C0'). Microstrip within 1.5 % of Hammerstad–Jensen, stripline within 1.6 % of Wheeler; IPC-2141 offset stripline is ~10 % high for narrow traces (not a bug).
  - `rlc.Extractor`: samples each track piece every `sample` mm; `section_key` cuts return zones + tracks (not pads/vias) along the normal (±window, 10 µm steps, runs rounded to 20 µm, slivers < 50 µm dropped) and caches solves per key. Inner copper slabs get the mean εr of their neighbours; outer layers are in air (no solder mask). Chains between junctions are cut into equal sections ≤ λ/10 at f_max (π ladder: R + L series, C/2 each end). Vias: barrel R; coax L to the nearest return via or Goldfarb partial L; Johnson C from the antipad radius sampled in the return planes. Pad C: C'(pad width) × length (SMD) or Johnson (THT). `dc_solver` scales all ladder R so P1→P2 matches `solver.simulate` (thermal off). Table rows merge when Z0 is within 5 % (`_similar`). `main_path` gives drawing cells.
  - `spice.write`: `.subckt NAME P1 … REF`, plain R/L/C, ASCII, group comments on their own lines (SPICE3 has no inline comments), `Meg` for 1e6. Verified in host ngspice (`/usr/bin/ngspice`): a matched 50 mm line's delay matches.
  - CLI: `python3 -m pcb_current_sim.extract BOARD PAD PAD … [--return NET] [--fmax 1G] [-o x.lib]`.
- GUI `wxgui/extract.py` `ExtractFrame` (Home tile "Trace R/L/C → SPICE", tool key `extract`): ports list (PadDialog, KiCad selection), return-net checklist (zone nets first, GND-like guessed), options; tabs Summary, Segments (+ vias/pads, CSV), Board (path coloured by Z0, steps > 10 % marked, "Select path in KiCad" via `KiCadLink.select_items(uuids)`), SPICE (save/copy), Schematic (`LadderCanvas`, reuses `schematic.draw_symbol`). Setup saved to scenario section `extract`. `sim/demo/smoke_extract.py` passes in the Flatpak.
- 2026-10-30 (user request after trying it): pours between pads failed, and the user wanted DC-style elements in the tool, plus C and L, all ideal ("we shall not have entire RCL models for those R, C and L elements themselves").
  - `path.build`: zones are components with `zonelink` edges (term = pad / via / track end; one per node, pad first); elements are `element` edges; nets grow through elements (`reachable_nets`) but never into return nets: a return-net pad is the single `ref` node (named REF). Joins now use `touches()` (disc vs pad shape) and tracks are split where vias / pads sit on their middle (both broke the +3V3 plane case on Magnus_Gateway: via ring on a pad edge, via mid-track).
  - `Extractor.zone_model`: mesh with `rz.coverage(faces=True)` (pitch >= 0.05 mm, ZONE_CELLS 60k), per-cell h above/below return (`Returns`), μ0 h per square, C = ε0 εr A/h; Kron reduction of conductance and inverse-inductance Laplacians on the terminals (LS.factorize), C split by harmonic weights; R+L branch per terminal pair, `pairs` dropped below 1e-6 relative. Validated: 20x4 mm pour -> C and L within 1 %, R = DC solver. Magnus +3V3 plane (In2, 14 terminals): 7.8 s.
  - `Returns` now rasterises each return layer once at 20 µm (point-in-polygon on 14k-vertex fills was 13 s of 23); `_q` rounds return edges 0.02 / 0.1 / 0.25 mm by distance for the section key.
  - Elements: `Element.model` "C" / "L" with fields `C`, `L` (DC solver: C open, L ideal link). Netlist kinds R, C, L and "D" (value (Vf, R)); `spice.write` expands D to `V_x` + `D_x` (.model DVF D(IS=1e-12 N=0.02)) + `R_x_s`. DC calibration is skipped when elements are present. `two_port(ext, a, b, "R"|"L")` (sparse) replaces ladder_r for pair R and the high-frequency loop L; pair C = all shunt C to REF.
  - GUI: `ElementDialog(models=..., dc=False)` (wxgui/app.py) offers R / diode / C / L; ExtractFrame has an Elements box (saved in scenario `extract.elements`); zones and elements in the Segments tab's lower table; pours drawn orange; diode symbol "D" in `schematic._body`.
- 2026-10-30 (user: "Where do R135 and R28 come from? A lot of symbols that don't actually exist"): SPICE names were sequential (R1…R135) and looked like board refdes; the Schematic tab took the fewest-hops path, so it drew weak pour branches (49 Ω / 183 µH) and dielectric-loss R. ## Switching Loop tool: decided 2026-10-30, to build BEFORE PDN (step 1 built 2026-10-30)
The user wants a reusable tool (not a study of one board; goodtorch is abandoned) for hard-switched power stages: layout → extracted network (steady state) + switching transient. The user calls it "a major part of the PDN suite".

## PDN and Trace → SPICE: design discussion (2026-10-29, not built yet)
The user asked to discuss the PDN tool before building it. Below are my proposals and the user's ideas. Nothing here is decided until the open questions at the end are answered.

### PDN tool: purpose and nature
- Question it answers: when the chip's load current changes fast, does the rail stay inside its noise budget?
  It computes Z(f) seen by the load and compares it with Z_t = V·ripple% / ΔI, from DC to f_max ≈ 0.35 / t_rise.
- **Linear, small-signal and frequency-domain, at the operating point. Not a transient simulator** (the user checked this explicitly).
  - Capacitors use their DC-bias value at the rail voltage, FETs their R_on, the VRM R + L.
  - No switching, regulator control loop or other nonlinear effects.
  - The proposed "load-step droop" (v2) is the linear time response from Z(f) via IFFT. It is not a nonlinear transient. True transients belong in SPICE, which the Trace → SPICE tool feeds.
- Solver: the plan below (2.5D mesh of the power copper over its return, about 0.25–0.5 mm). Each link is R_s(f) with skin effect plus jωμ0·h; each cell has a shunt C + G to the return; εr(f) and tanδ(f) come from the shared stackup.
- Proposed steps:
  1. extract the rail's copper (power net + return net);
  2. mesh it;
  3. ports: decaps (series RLC + mounting L from pads, traces and vias), VRM (R + L), load ports at the IC power pins;
  4. Z(f) at each load and between ports;
  5. analyses: target check, plane resonances (frequency, Q, voltage maps), per-decap contribution, loop L(f), which moves here from the DC tool.
- **Inputs from the project:** zones, tracks, vias and pads of the power and return nets; the stackup; capacitor footprints between rail and GND (Value, package, MPN → library match); pad and via geometry for mounting L; IC pins on the rail (suggested load ports); the DC tool's V and load rows (VRM position, load, current, voltage).
- **Inputs from the user:** the rail (power + return net, suggested from the DC rows); the target (V, ripple %, ΔI, f_max, optional frequency mask); the VRM (R_out, L_out or loop bandwidth); load ports (KiCad selection works); confirming each decap's library model, with DC-bias derating at the rail voltage; an optional package / die model (L_pkg, C_die); grid pitch and frequency range.
- **Outputs and their use:**
  - Z(f) at each load against the target, for bare board, + decaps and + VRM: pass/fail and the failing frequency.
  - Anti-resonance peaks, e.g. 10 µF ∥ 100 nF.
  - Decap table: effective C at bias, ESL, mounting L, effective SRF, distance to the load, "useful up to", flags for too far / redundant.
  - What-if: Z with each cap removed, and a sensitivity ranking (how far the BOM can be trimmed).
  - Plane resonances and mode-shape maps: where to place caps, and EMI hints.
  - Loop L(f) from VRM to load.
  - Layout warnings: power copper with no return under it, slots and splits, long cap-to-via traces.
  - Exports: Touchstone .sNp, CSV, PDF, ParaView.
- **v2 candidates:** load-step droop (linear, from Z(f)), a decap optimiser (cheapest set from the library that meets the target), coupling between rails, virtual "what-if" decaps.
- **Limits:**
  - It is 2.5D, not full-wave; good to about the low GHz.
  - 2-layer boards without a solid return plane are much less accurate (warn).
  - VRM control loop not modelled.
  - The return is the ideal reference per plane pair, so no ground bounce between distant GND pins in v1.

### User's idea: components with any model between any pins (in PDN, generalising DC elements)
- The user wants any 2+ pin device placed between pads with R, L, C, a transmission line or a small network as its internal model, as part of the PDN.
- My proposal: make a **"component" (pins + model) the core concept of PDN**.
  - Decaps, the VRM, ferrite beads, sense resistors, load switches and cables are all components. The load is a current-source port.
  - A component bridging nets (VDD → bead → VDDA) makes the tool solve the joined rails together, as DC does across nets.
- Solver cost: a 2-pin component is an admittance stamp between two pad super-nodes; an N-pin one is an N×N Y(f) block (internal nodes added, or folded in with a Schur complement). Cheap.
- **Share components with DC & Thermal (recommended):** define once. DC uses the DC limit (L → DCR, C → open, line → R′·length); PDN uses Z(f). Existing DC elements become pure-R models.
- Model types proposed:
  1. R/L/C topologies (series RLC, parallel RLC, R+L ∥ C, …), 2 pins;
  2. a component library part (Q, SRF, ESR, ESL, DC bias);
  3. a Z(f) table or .s2p, needed for **ferrite beads**;
  4. a transmission line (Z₀, delay or length, loss, R_dc), as 2 pins + return or 4 pins (a pair at each end), for cables, harnesses, connector pin pairs, busbars;
  5. a small internal network (R, L, C, TL, coupled inductors K, internal nodes), for 3+ pin parts such as π-filters, X2Y / feedthrough caps, common-mode chokes, a buck output stage. Reuse the Matching tool's ladder editor.
  6. a Touchstone N-port with a pin map (vendor connector, package and IC power-pin models), fixed.
- **Rule:** a 2-pin part can only hold a single impedance Z(f) between its pins; nothing "to ground" without a ground pin. A 3+ pin part may hold a network with one pin as its internal reference. Enforce this in the editor.
- A TL model is only worth it when the part is longer than about λ/10. On FR4 at 1 GHz λ ≈ 150 mm, so SMD parts are lumped and cables or busbars need it. Option: n RLC sections as a distributed approximation.
- Extra outputs: current, voltage and AC power per component against f (bead ripple loss, sharing between parallel caps); **filter-peaking flags** (bead + decap LC peak); sensitivity of Z to each component; multi-rail results.
- Limits: linear models at the operating point; GND pins connect to the local reference (no ground bounce in v1).

### User's idea: Trace → SPICE, an interconnect extractor (separate tool)
- The user wants to pick any two pads and get an RLC (transmission-line) equivalent of the trace plus its stray C and L, to drop into SPICE. The main purpose: SPICE models of traces.
- Proposal: a separate tile "Trace → SPICE" under SIGNAL & FIELDS. It is the first piece of SI / extraction, and PDN can reuse its parts.
- Steps:
  1. pick 2+ pads (KiCad selection);
  2. trace the copper path along tracks and vias (branches and stubs become internal nodes);
  3. split into segments wherever width, layer, reference plane or a via changes the cross-section;
  4. per-unit-length RLGC per segment: L′ = Z₀√εeff/c and C′ = √εeff/(Z₀c) from microstrip (Hammerstad–Jensen, already in `matching/microstrip.py`) or stripline formulas, later a 2D field solve; R′ = DC + skin effect (exact DC R between the pads is available from the DC solver); G′ from tanδ(f); vias get L, C and barrel R;
  5. cut into sections of at most λ/10 at f_max (or set by rise time) and cascade.
- Outputs:
  - SPICE `.subckt` as a universal RLC(G) ladder (any SPICE);
  - a compact alternative using SPICE line elements (`T` lossless, `LTRA` lossy; ngspice and LTspice);
  - a per-path summary (Z₀ per segment, total delay, R, L, C, the reflection points);
  - Touchstone `.s2p` for the Matching and PDN tools;
  - a segment table and the path highlighted on the board.
- Limits:
  - The return path sets L. Reliable with a solid reference plane; on 2-layer boards with no plane, use the nearest GND copper and warn.
  - Paths through zones are not traces: hand them to the PDN mesh, or fall back to DC R plus an estimate.
  - Skin effect in a plain ladder is fixed at one f; an optional R-L network per section makes it frequency-dependent.
  - Coupling to neighbouring traces (mutual L and C, crosstalk) is v2, shared with the SI 2D solver.
- Estimated size: about one session; much smaller than PDN.

## Plan agreed 2026-10-29: a simulation suite in several windows
The user looked at how the commercial tools group their simulations and agreed this structure:
- Cadence splits PowerDC (DC IR plus electro-thermal) from PowerSI and OptimizePI (AC PDN, decaps).
  Aurora covers impedance, crosstalk and return path; Celsius is thermal; Clarity is full-wave.
- Ansys SIwave holds DC, SYZ, resonance and EMI in one tool. Icepak does thermal, fed by SIwave's loss maps.
- Keysight PIPro holds DC IR, electro-thermal, AC Z, resonance and decap optimisation, all with one shared setup.

The decisions:

1. **DC & Thermal**: the current window.
   - Contents: DC current density, IR drop, resistance elements, electro-thermal, pulse/fusing and DC B-field maps.
   - Later: electromigration lifetime (Black), via barrel fatigue, tolerance Monte Carlo, component self-heating and airflow.
2. **PDN (AC power integrity)**: the first new window to build.
   - Contents: Z(f) against target impedance (Z_t = V·ripple / I_step), a decap table (auto-detect C footprints; ESR, ESL and mounting L), a VRM model (R + L), plane resonances, L(f) and EMI from resonances.
   - Later: decap optimisation.
   - It shares the VRM and load definitions with window 1, as PIPro does: the "V" and "load" rows can be imported.
   - **Loop inductance moves here** as L(f), with the current DC-pattern value as its low-frequency point. The DC B maps stay in window 1.
   - Solver plan:
     - A frequency-domain mesh of the power-net copper on a coarser AC grid (about 0.25 to 0.5 mm).
     - Each link: (R_s,pow(f) + R_s,ret(f) + jω·μ0·h) / g, where g = w/l comes from the existing link conductance (G = σ·t·g).
     - Skin effect: R_s = ρ / (δ·(1 − e^(−t/δ))).
     - h is the dielectric distance to the nearest return-net copper. Treat return planes on both sides as two in parallel.
     - Each cell gets a shunt jωC + ω·C·tanδ to the return, with C = ε0·εr·A / h. Defaults are εr = 4.3 and tanδ = 0.02.
     - Power-net vias: L ≈ μ0·Δz/(2π)·ln(s/r), with s the distance to the nearest return via.
     - Ports are super-nodes against the return as reference: decaps as series RLC, VRM as R + L, load = the measured port.
     - Warn where power copper has no return copper under it.
     - Why not reuse the DC current pattern for L: at PDN frequencies the return current runs under the power copper, while the DC return spreads out, so the DC-pattern L is too large.
3. **Signal integrity & fields**:
   - Trace Z₀, effective permittivity and crosstalk from a 2D cross-section Laplace solve.
   - Return-current path at frequency (moved here from PDN).
   - HV E-field and clearance/creepage.
4. **Full-wave export**: openEMS, for antennas and S-parameters.

Framework, to build first:
- Launching: superseded by the update below: a Suite (Home) button plus a direct DC & Thermal button, as two actions in the IPC `plugin.json`.
- A shared board, stackup and materials panel (εr and tanδ get added).
- One scenario file, `board.current_sim.json`, with one section per window. Old files must keep loading.
- The shared result viewer (2D, 3D, tables, ParaView), extended with frequency plots for PDN.

**Matching & Tolerance tool.** Circuit-level, pure numpy, no external solver.
- Purpose, in the user's words: play with *real* component values and see if the matching network still works across tolerances.
- **Ladder builder only.** Series and shunt slots, each holding L, C, R, a transmission-line section (Z₀ and εeff from the stackup) or an open/short stub. A netlist editor and KiCad import are deferred.
- Input and output ports against ground. Z_S and Z_L can be:
  - a constant R + jX;
  - an RLC model;
  - optionally a `.s1p` file, for example the antenna S11 from openEMS later.
- Real models:
  - **L:** tolerance (±% or ±nH), DCR, Q at f_Q, SRF. Model: L in series with R(f) = DCR + k√f (k fitted to Q), in parallel with C_p = 1/((2π·SRF)²·L).
  - **C:** tolerance (±% or pF codes A/B/C/D = 0.05/0.1/0.25/0.5), Q or ESR, ESL or SRF, C0G against X7R (tempco, DC bias).
  - **R:** tolerance, L_s, C_p.
- **Vendor S2P:** only if cheap. Plan: our own small Touchstone parser, with an S2P part used as a fixed element (no tolerance). Drop it if it costs more than that.
- Analysis:
  - corners (2^N);
  - Monte Carlo (10k–100k samples), with **uniform or Gaussian (3σ = tolerance) selectable in the UI**;
  - a bounded worst-case optimiser, because resonant responses are non-monotonic and corners can miss the worst case;
  - sensitivity / variance contribution;
  - optional temperature sweep.
  - Batched: ABCD cascade over samples × frequencies.
- Specs are multi-band: RL / VSWR / IL limits per band.
- Outputs:
  - a Smith chart with the nominal curve and the MC cloud or envelope;
  - S11, S21 and VSWR against f, with min/max and 5–95% bands;
  - IL and efficiency;
  - yield, overall and per band;
  - histograms and a sensitivity chart;
  - a BOM.
- Step 2: synthesise L / π / T from Z_S and Z_L, snap to E-series or library values, then design centering (maximise yield).

**3D tools (discussed):**
